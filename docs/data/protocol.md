# Протокол обмена host <-> I2C

Бинарный протокол моста между последовательным транспортом (USB VCP, UART,
UNIX-сокет эмулятора) и шиной I2C.

- Версия протокола: **1**
- Транспорт: любой байтовый поток, протокол от транспорта не зависит
- Кадрирование: **COBS/R** + терминатор `0x00`
- Целостность: **CRC-16/CCITT-FALSE** (poly `0x1021`, init `0xFFFF`)
- Порядок байтов в многобайтовых полях: **little-endian**

## 1. Кадрирование

Сырой кадр (см. разделы 2-3) кодируется COBS/R и завершается байтом `0x00`:

```
на проводе:  COBS/R(raw_frame) 0x00
```

COBS/R гарантирует отсутствие байта `0x00` внутри закодированного кадра,
поэтому `0x00` — однозначная граница кадра и точка ресинхронизации после
мусора или обрыва связи. Пустые кадры (подряд идущие `0x00`) игнорируются.

Поверх COBS/R передаётся CRC-16, потому что COBS сам по себе ошибок не
обнаруживает.

## 2. Кадр запроса (host -> bridge)

| Смещ. | Размер | Поле | Описание |
|------:|-------:|------|----------|
| 0 | 1 | `ver_cmd` | старший nibble — версия (`1`), младший — команда |
| 1 | 1 | `msg_id` | `0x00..0x7F`, бит 7 = 0 (запрос) |
| 2 | 1 | `flags` | биты 0..1 — размер регистра, остальные зарезервированы (0) |
| 3 | 1 | `addr` | 7-битный адрес I2C-устройства без сдвига |
| 4 | 1 | `len` | `READ` — сколько байт читать; остальные — длина `data` |
| 5 | 2 | `reg` | адрес регистра, LE; значащих байт — по `flags` |
| 7 | `len` | `data` | payload; у `READ` отсутствует |
| 7+`len` | 2 | `crc16` | CRC-16 по байтам `0..6+len-1`, LE |

Минимальный запрос — 9 байт (`READ` без данных). Максимум —
`PROTO_MAX_DATA = 128` байт payload.

## 3. Кадр ответа (bridge -> host)

| Смещ. | Размер | Поле | Описание |
|------:|-------:|------|----------|
| 0 | 1 | `ver_cmd` | та же команда, версия `1` |
| 1 | 1 | `msg_id` | `0x80 \| request.msg_id` |
| 2 | 1 | `flags` | эхо `flags` запроса |
| 3 | 1 | `addr` | эхо `addr` запроса |
| 4 | 1 | `len` | фактическая длина `data` |
| 5 | 1 | `status` | код результата (раздел 5) |
| 6 | `len` | `data` | прочитанные данные / битовая карта / info |
| 6+`len` | 2 | `crc16` | CRC-16 по байтам `0..5+len-1`, LE |

## 4. Флаги

| Бит(ы) | Поле | Значение |
|--------|------|----------|
| 0..1 | `reg_size` | `0` — нет регистра, `1` — 1 байт, `2` — 2 байта |
| 2..7 | резерв | должны быть `0`; иначе `PARAM` |

`reg_size` имеет смысл только для `READ` и `WRITE`. Для остальных команд
поле должно быть нулевым.

## 5. Коды результата

| Код | Имя | Описание |
|----:|-----|----------|
| `0x00` | `OK` | успешно |
| `0x01` | `NACK_ADDR` | устройство не подтвердило адрес |
| `0x02` | `NACK_DATA` | устройство не подтвердило байт данных |
| `0x03` | `TIMEOUT` | таймаут транзакции (SCL удержан) |
| `0x04` | `BUS_ERROR` | ошибка шины, потеря арбитража |
| `0x05` | `BUSY` | шина занята |
| `0x06` | `PARAM` | неверные флаги/адрес/длина |
| `0x07` | `UNKNOWN_CMD` | неизвестная команда |
| `0x08` | `CRC` | ошибка CRC (в v1 ответ не отправляется) |
| `0x09` | `FRAME` | битая структура/версия (ответ не отправляется) |
| `0x0A` | `OVERFLOW` | переполнение внутреннего буфера |
| `0x0B` | `NOT_SUPPORTED` | команда не поддерживается |

Правила обработки ошибок:

- ошибка COBS/R, пустой кадр, неверная версия, неверный CRC, слишком
  длинный кадр — кадр **молча отбрасывается**, счётчик инкрементируется;
- CRC валиден, но поля или команда некорректны — отправляется ответ с
  `PARAM` или `UNKNOWN_CMD` (эхо заголовка запроса, `len = 0`);
- хост обнаруживает потерянный кадр по таймауту (рекомендуется 100 мс).

## 6. Команды

| Код | Команда | Запрос | Ответ |
|----:|---------|--------|-------|
| `0x1` | `READ` | `reg`, `len` = сколько читать | `data` = `len` байт |
| `0x2` | `WRITE` | `reg`, `data` длиной `len` | `len = 0` |
| `0x3` | `SCAN` | `data` пусто или `[from, to]` | 16 байт битовой карты |
| `0x4` | `INFO` | `len = 0` | 8 байт (см. 6.1) |
| `0x5` | `PING` | произвольный payload | эхо payload |
| `0x6` | `BUS_RECOVER` | `len = 0` | `len = 0` |
| `0x7` | `STATS` | `len = 0` | 14 байт (см. 6.2) |
| `0x9..0xF` | события | зарезервировано | — |

### 6.1. `READ`

- `len = 0` — проба адреса (проверка ACK), данные не возвращаются.
- `reg_size = 0` — прямой `Master Receive`.
- `reg_size = 1` или `2` — запись регистра, repeated start, чтение
  (`HAL_I2C_Mem_Read`).

### 6.2. `WRITE`

- `reg_size = 0` — прямой `Master Transmit`.
- `reg_size > 0` — запись регистра и данных одной транзакцией
  (`HAL_I2C_Mem_Write`).

### 6.3. `SCAN`

- payload пуст — сканируется весь диапазон `0x08..0x77`;
- payload 2 байта `[from, to]` — сканируется заданный диапазон,
  `from <= to`, адреса не больше `0x7F`;
- ответ — 16 байт: бит `N` байта `N/8` установлен, если адрес `N`
  ответил ACK; биты вне диапазона сброшены.

### 6.4. `INFO`

| Смещ. | Размер | Поле |
|------:|-------:|------|
| 0 | 1 | версия протокола (`1`) |
| 1 | 1 | `caps` — битовая маска поддерживаемых команд |
| 2 | 1 | `PROTO_MAX_DATA` |
| 3 | 1 | версия прошивки: major |
| 4 | 1 | версия прошивки: minor |
| 5 | 1 | версия прошивки: patch |
| 6 | 2 | скорость шины, кГц, LE |

`caps` — бит с номером команды: `bit1` = READ, `bit2` = WRITE,
`bit3` = SCAN, `bit4` = INFO, `bit5` = PING, `bit6` = BUS_RECOVER,
`bit7` = STATS.

### 6.5. `STATS`

14 байт, 7 счётчиков по 2 байта LE (с переполнением):

| Смещ. | Счётчик |
|------:|---------|
| 0 | `rx_ok` — принято валидных кадров |
| 2 | `rx_crc_err` |
| 4 | `rx_overflow` |
| 6 | `rx_frame_err` |
| 8 | `tx_drop` |
| 10 | `i2c_nack` |
| 12 | `i2c_timeout` |

## 7. Пример

Чтение 2 байт из устройства `0x50`, регистр `0x1234` (2 байта),
`msg_id = 0x05`:

```
запрос (raw):   01 05 02 50 02 34 12 <crc16>
ответ   (raw):  11 85 02 50 02 00 AA BB <crc16>
```

`msg_id` ответа — `0x85` (`0x80 | 0x05`). На проводе оба кадра
дополнительно COBS/R-кодируются и завершаются `0x00`.

## 8. Поведение моста

- Запросы обрабатываются последовательно, один за другим; ответы
  отправляются в порядке обработки. Рекомендуется не держать больше
  одного незавершённого запроса на хосте.
- Повторная отправка `WRITE` приведёт к повторной записи: дедупликации
  по `msg_id` в версии 1 нет.
- `SCAN` блокирует цикл обработки на время сканирования (до ~0.2 с для
  полного диапазона при таймауте 2 мс на адрес).
- `BUS_RECOVER` освобождает шину: 9 импульсов SCL, STOP, повторная
  инициализация I2C. Если линии не освободились — `BUS_ERROR`.

## 9. Проверка на хосте

Контрольная сумма и кадрирование проверяются стандартными средствами
Python:

```python
import binascii
from cobs import cobsr

raw = bytes.fromhex("01050250023412")
crc = binascii.crc_hqx(raw, 0xFFFF)
frame = cobsr.encode(raw + crc.to_bytes(2, "little")) + b"\x00"
```

Для декодирования ответа:

```python
body = cobsr.decode(frame_without_terminator)
assert binascii.crc_hqx(body[:-2], 0xFFFF) == int.from_bytes(body[-2:], "little")
```
