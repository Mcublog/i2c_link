# AGENTS.md

Инструкции для ИИ-агентов, работающих в этом репозитории — шаблонном
проекте для разработки встроенного ПО (embedded) на C/C++.

## Структура проекта

- **`app/`** — платформонезависимый код: логика приложения, интерфейсы
  подсистем, утилиты. Не содержит кода, зависящего от железа или ОС
  (никаких `f_open`, `fopen`, регистров МК и т.п.). Здесь размещаются
  только *интерфейсы* (`.h`) и платформонезависимая логика.
- **`bsp/`** — реализация кода под конкретную плату/платформу. Каждая
  платформа — свой подкаталог:
  - `bsp/desktop/impl/` — хостовые реализации (GPIO, файловая система, таймеры);
  - `bsp/fntester_pcb/impl/`, `bsp/fntester_pcb/io/` — реализация для
    платы fntester_pcb (STM32F072).
  - Интерфейс объявляется в `app/` (например `app/storage/storage.h`),
    реализация живёт в `bsp/<платформа>/`.
- **`arch/`** — низкоуровневые модули под платформу/архитектуру:
  критические секции, systime, задержки, IO-моки. `arch/desktop/` — хост-сборка,
  `arch/stm32f072/` — МК.
- **`test/`** — юнит-тесты под desktop (компилируются и запускаются на хосте).
  Один тест — свой подкаталог (`test/smoke/` и т.п.). Имя цели — `utest_<name>`.
- **`hwtest/`** — тесты на железе (в обычную сборку не входят,
  `add_subdirectory(hwtest)` закомментирован).
- **`utils/`** — хостовые утилиты (в прошивку не входят). Каждая утилита —
  свой подкаталог (`utils/hello/` — пример-заготовка).
- **`scripts/`** — вспомогательные хостовые скрипты (не входят в прошивку).
- **`resources/`** — файлы ресурсов: SVD-описания, сгенерированные данные, даташиты.
- **`docs/`** — документация проекта.
- **`targets/`** — исполняемые цели сборки:
  - `targets/emu/` — эмулятор прошивки на хосте;
  - `targets/fntester_pcb/` — прошивка под fntester_pcb (STM32F072,
    CubeMX + HAL).
- **`libs/`** — сторонние/разделяемые библиотеки (+ `libs/libs.cmake`,
  который объявляет их источники и include-пути). Абстракция
  последовательного транспорта (`Serial`, `ios_ctl_t`) — `libs/serdev`;
  для МК реализации транспортов живут в `arch/<архитектура>/`
  (например `UsbSerial`).

## Правила

1. Платформонезависимый код размещается только в `app/`. Код, зависящий от
   платы или платформы, — в `bsp/` (реализация под конкретную плату/платформу)
   или `arch/` (низкоуровневые модули под платформу).
2. В заголовках с `#ifdef __cplusplus` / `extern "C"` внутри блока
   размещаются **только объявления функций**. Типы данных и макросы — вне блока.
3. Юнит-тесты именуются с префиксом `utest_` (например, `utest_smoke`).
4. Заголовочные файлы (`app/`) содержат Doxygen-комментарии (`/** @brief ... */`)
   для **всех** публичных функций (в блоке `extern "C"`), типов данных
   (`struct`, `enum`, `union`, `typedef`) и макросов/констант.
   Структурные поля документируются `/** @brief ... */` блоками.
   Комментарии на русском языке. Функциональные комментарии живут в заголовках,
   а не в `.c`/`.cpp` файлах.

## Сборка и тесты

- Конфигурация: `cmake -S . -B build` (перезапуск обязателен после
  добавления/удаления файлов — исходники собираются через `file(GLOB ...)`).
  Для отладки конфигурировать с `-DCMAKE_BUILD_TYPE=Debug`.
- Сборка: `make -C build` (генератор Unix Makefiles). Точечная сборка цели —
  по короткому имени из `make -C build help` (например `make -C build utest_smoke`);
  путь к бинарнику как цель make не поддерживается.
- Цели (из `build/`):
  - эмулятор: `./targets/emu/emu` (сервер, не завершается сам — запускать
    с таймаутом);
  - прошивка fntester_pcb: `build/targets/fntester_pcb/fntester_pcb`
    (+ `.hex`/`.bin`);
  - хост-утилита: `./build/utils/hello/hello`;
  - тесты: `./test/smoke/utest_smoke` и др.
- Тесты можно запустить все: `make -C build utest` (через `ctest`).
- Вспомогательные Make-цели: `make firmwares` (прошивка), `make emuls`
  (эмулятор), `make utils`, `make utest`.

## Стиль

- Текст документов и код, за редким исключением (например, большие
  таблицы), форматируются по 80 символов в строке.
- Новые модули логирования определяют `LOG_MODULE_NAME` и `LOG_MODULE_LEVEL`,
  затем подключают `log_libs.h`.
- C/C++ файлы разбиваются на секции разделителями
  `//>>---------------------- <Подпись>` ... `//<<----------------------`
  в порядке: `Global`, `Local`, `Private`, `Public`:
  - `Global` — глобальные переменные с внешним связыванием (без `static`);
  - `Local` — локальные типы данных, статические (внутренние) переменные
    и локальные переменные;
  - `Private` — локальные функции и методы;
  - `Public` — публичные функции.
  Блок управления логированием (`//>>---------------------- Log control`) тоже
  оформляется этими разделителями и идёт первым.
- Комментарии в коде со спец-тегами пиши в самом начале, например: `// TODO:`,
  `// NOTE:` и так далее.
- Дефайны, объявляющие теги, именуются с постфиксом номера тега
  (например, `REC_TAG_DATE_TIME_1012`, а не `REC_TAG_DATE_TIME`).
- Статические переменные в `.c`/`.cpp` файлах (в том числе локальные
  `static` внутри функций) и переменные-члены классов именуются
  с префиксом `m_`: `m_counter`, `m_state`.
- Константы (`const`/`constexpr`, включая константные таблицы) именуются
  в стиле `k` + PascalCase: `kMaxTimers`, `kCrcTable`.
