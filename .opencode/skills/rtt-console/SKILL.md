# rtt-console

Работа с консолью прошивки через SEGGER RTT по отладчику J-Link PLUS.
Программа rtt-console подключается к МК по SWD, запускает RTT-сервер,
печатает входящие логи прошивки и умеет подавать команды (например,
аппаратный сброс).

## Предусловия

- J-Link PLUS подключён к USB (lsusb: `1366:0101 SEGGER J-Link PLUS`).
- Плата fntester_pcb питается; при питании только через J-Link
  используй `-p`.
- Прошивка собрана с поддержкой RTT (в сборку fntester_pcb входит
  `libs/hw/third_party/SEGGER_RTT_V762c`).

## Ключевые факты

- Бинарь: `~/.local/bin/rtt-console` (v0.2.7, Python + pylink).
- Таргет по умолчанию: STM32F072CB, интерфейс SWD, скорость auto.
- Подключён один J-Link: serial 69665469; `-i` нужен только при
  нескольких подключённых отладчиках.
- Процесс НЕ завершается сам — всегда запускай с `timeout`.
- Команды перехватываются самой консолью (НЕ прошивкой):
  - `reset` — аппаратный сброс МК через J-Link;
  - `power_on` / `power_off` — питание таргета через J-Link;
  - `reconnect` — переподключение к J-Link;
  - `clear` — очистка экрана.
- Прочий введённый текст уходит в RTT down-buffer 0 и прошивкой
  игнорируется (в прошивке нет `SEGGER_RTT_Read`).
- Без `-p` rtt-console при подключении отключает питание таргета через
  J-Link (`jlink.power_off()`); при внешнем питании на плату это
  не влияет.
- Логи прошивки идут через `printf` -> SEGGER RTT
  (`libs/debug/log_libs.c` + ретаргет `SEGGER_RTT_Syscalls_GCC.c`).
  Формат строки: `<prefix>> <module>: <сообщение>`, prefix =
  `err`/`wrn`/`inf`/`dbg`.

## Helper-скрипт

В проекте есть обёртка `scripts/rtt.sh`. Она запускает
rtt-console с timeout, подаёт команду через stdin и сохраняет вывод.

    scripts/rtt.sh -h        # справка

Параметры:
- `-t TARGET` — имя чипа (по умолчанию STM32F072CB);
- `-c CMD` — команда консоли (например `reset`); пусто = только чтение;
- `-w SECONDS` — время работы, с (по умолчанию 10);
- `-o FILE` — сохранить вывод в FILE;
- `-p` — включить питание таргета через J-Link.

## Сценарии

### Снять текущее состояние (без сброса)

    scripts/rtt.sh -w 8 -o state.log

### Сбросить плату и снять boot-логи

    scripts/rtt.sh -c reset -w 20 -o boot.log

### Питание таргета через J-Link

    scripts/rtt.sh -p -c reset -w 15 -o boot.log

## Анализ логов

- Проверь баннер подключения в начале файла:
  `Connected to: STM32F072CB`, `Connected to Little-Endian Cortex-M0`.
  Отсутствие баннера или `ERROR:` в первых строках — проблема
  подключения.
- Ожидаемые строки boot-лога (main.c, application.cpp):
  - `inf> main: SYSCLK = <freq>` / `HCLK` / `PCLK`;
  - `inf> app: fw: <версия>`;
  - `inf> app: tick: <n> s` (раз в секунду);
  - `inf> app: application started`.
- Ищи `err>`/`wrn>` по всему логу — это ошибки/предупреждения.
- Таймстемпов в логах нет — очерёдность и частоту суди по порядку строк.

## Неисправности

- `ERROR: JLink libs not found` — не найдена библиотека pylink/J-Link;
  укажи путь явно: `-p /opt/SEGGER/JLink_V786/libjlinkarm.so`.
- `Cannot connect` / повторные реконнекты — J-Link занят другим
  процессом (JLinkExe, JLinkRTTViewer, другой rtt-console).
- Подключено несколько J-Link — добавь `-i <serial>`.
- Нет данных после сброса — плата, возможно, питается только через
  J-Link; запусти с `-p`.
- Пустой лог при чтении работающей платы — RTT-сервер не запущен
  (старая прошивка без RTT) или плата выключена.

## Ограничения

- `reset` перезагружает МК.
- Произвольные команды (не из списка консоли) прошивка не обрабатывает.
- Вывод не содержит таймстемпов; при высокой нагрузке RTT-буфер может
  переполняться (SEGGER_RTT_MODE_NO_BLOCK_SKIP) и терять данные.
